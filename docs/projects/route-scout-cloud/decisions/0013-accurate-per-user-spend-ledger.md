# ADR-0013: Single-User Accurate Per-User Spend Ledger Ahead of Deferred Multi-User Stripe Billing

* **Date:** 2026-10-28
* **Status:** Accepted
* **Deciders:** Eric (Project Owner), Antigravity (Orchestrator)
* **Related Work Package:** [`WP-04.5`](../plan/active/WP-04.5-user-spend-tracking.md)

## 1. Context & Problem Statement

With Milestone 4 complete, the original Tier 2 Roadmap scheduled **Milestone 5 (Phase 2)** as a multi-user Stripe Checkout prepaid wallet system (`wallet.json`, Stripe webhooks, `HTTP 402` balance gating, and a `1.15x` cost-recovery markup). However, the project remains a private single-owner deployment (`ALLOWED_EMAILS`), and introducing Stripe Checkout, webhook secret management, and multi-user prepaid balance gating adds unnecessary operational complexity before multi-user onboarding is desired.

At the same time, the owner requires **accurate, on-demand visibility into user AI, external API, and underlying AWS infrastructure spend** generated by the application—prioritizing:
1. **Accuracy (#1 Requirement):**
   * Every billed Amazon Bedrock token (input, output, cache-read, cache-write) and every billed external grounding API request (Google Places Text Search Enterprise and Brave Web Search) must be captured and priced accurately across all AI endpoints—including non-streaming Copilot alert generation, day-title generation, and multi-iteration streaming/non-streaming Route Scout turns, even when a turn later fails, hits `max_tokens`, produces malformed JSON, or is aborted mid-stream.
   * **Full Unit-Economics Coverage (Compute, S3, CDN & Account Overhead):** Pricing future Phase 2 users on AI + tool calls alone risks losing money on AWS Lambda compute, S3 `GET`/`PUT`/`LIST` operations, CloudFront request/egress transfer, ECR container storage, and CloudWatch logs—especially when low-volume AWS Free Tier discounts mask marginal infrastructure costs. M4.5 must therefore also capture **bottom-up allocated AWS infrastructure cost at full `us-east-2` list rates** per turn/operation and support **top-down account-level AWS bill reconciliation** to calculate the true break-even markup required for Phase 2.
2. **Simplicity (#2 Requirement):** Zero new AWS infrastructure or monthly idle cost, no mandatory Web Studio UI dashboard clutter, and instant on-demand inspection from the terminal (`./scripts/check_spend.sh`), authenticated API (`GET /api/spend`), or S3 object storage (`s3://<AppDataBucket>/users/{email}/spend.json`).

Furthermore, live auditing of the M3/M4 codebase and the AWS Price List API (`aws pricing`) in `us-east-2` revealed five concrete accuracy gaps that must be addressed by design:
* **Gap 1 — Non-streaming calls discard token usage:** `AwsBedrockHarnessAdapter.generate()` (`ConverseCommand`) ignores `response.usage`, so `/api/copilot/generate` and `/api/copilot/day-title` currently report zero token usage.
* **Gap 2 — Failed, truncated, or aborted turns lose prior billed usage:** In `generate()` and `generateStreamWithTools()`, throwing on `stopReason === 'max_tokens'`, `MalformedAiResponseError`, or iteration N+1 failures discards token and tool usage already billed by Bedrock, Brave Search, and Google Places in earlier steps of the same turn.
* **Gap 3 — AWS Price List API cannot be queried dynamically at runtime:** Bedrock SKUs in `aws pricing` are split across three service codes (`AmazonBedrock`, `AmazonBedrockFoundationModels`, `AmazonBedrockService`) with inconsistent model naming, units (`1K tokens` vs `1M tokens`), and regional inference profile premiums (`us.*` carries a 10% geographic premium over `global.*` on newer models such as `us.moonshotai.kimi-k3` and `us.amazon.nova-2-lite-v1:0`). In addition, `zai.glm-5.3` is returned by Bedrock model discovery in `us-east-2` but has no published SKU in the AWS Price List API for `us-east-2`.
* **Gap 4 — External tool free-tier vs. list-price ambiguity:** Google Places Text Search Enterprise (`places.regularOpeningHours` in `X-Goog-FieldMask`) carries a `$0.035/call` list price with a permanent `1,000 calls/month` free tier on Google Cloud, whereas Brave Web Search costs `$0.005/call`. Recording only list price overstates actual out-of-pocket charges during low-volume months, while recording `$0.00` hides marginal tool consumption.
* **Gap 5 — Unallocated AWS Compute, S3, CloudFront & Shared Account Overhead:** AWS Lambda (`512 MB` execution duration + request fees), Amazon S3 (`GET`/`PUT`/`LIST` + storage bytes), CloudFront (HTTPS request fees + egress bytes), Amazon ECR (container image storage), and CloudWatch Logs are billed at the AWS account level and partially masked at low volume by the AWS Free Tier. Without bottom-up per-user infrastructure attribution and top-down account reconciliation, Phase 2 user pricing would under-recover real cloud overhead.

## 2. Decision Drivers

* **Accuracy First:** Never drop billed tokens or HTTP 2xx external API calls on error/abort paths; never guess fallback prices for unpriced models ([AGENTS.md Rule 12](../../../../AGENTS.md)); eliminate IEEE-754 floating-point drift in cumulative rollups.
* **Simplicity Second:** Reuse the existing `AppDataBucket` S3 persistence pattern ([ADR-0003](0003-s3-atomic-json-persistence.md)), `KeyedMutex` local concurrency ([ADR-0008](0008-local-storage-in-process-lock.md)), and local-dev isolation ([ADR-0004](0004-hybrid-local-dev-mode.md)) with zero new AWS resources.
* **On-Demand Inspection Without UI Bloat:** Provide a one-command CLI inspector (`./scripts/check_spend.sh` / `npm run spend`) and a clean authenticated JSON endpoint (`GET /api/spend`) rather than building a billing UI in the Web Studio.

## 3. Considered Options

* **Option A: Defer all spend tracking until Phase 2 M5 (Stripe Prepaid Wallet) or rely solely on AWS Cost Explorer.**
  * *Rejected:* AWS Cost Explorer has a 24–48 hour delay, cannot attribute spend per application user or per operation (`scout_chat` vs `copilot_alert`), and does not include Google Places or Brave Search spend. Implementing full Stripe Checkout now violates the single-user simplicity requirement.
* **Option B: Query the AWS Price List API dynamically at runtime and estimate costs only on successful HTTP 200 responses.**
  * *Rejected:* Dynamic `aws pricing` queries are brittle across inconsistent AWS service codes, add IAM/latency overhead, fail on unindexed SKUs (`zai.glm-5.3`), and miss all tokens/tool calls consumed during failed, truncated, or aborted requests.
* **Option C (Chosen): Insert Milestone 4.5 (M4.5) with a Verified `us-east-2` Pricing Catalog, Fail-Closed Model Admission, Per-Turn `finally` Usage Capture, Integer Nanodollar Accounting, and Atomic S3/Local Spend Ledger (`spend.json`).**

## 4. Decision Outcome

Choose **Option C** and define **Milestone 4.5 (M4.5): Accurate Per-User Spend Tracking & On-Demand Spend Inspection** in Phase 1 while keeping Milestone 5 (Stripe Prepaid Checkout) deferred to Phase 2:

1. **Provider-Agnostic `AiHarnessAdapter` Spend Seam & Verified `us-east-2` Pricing Catalog (`aiService.ts` & `spendPricingCatalog.ts`):**
   * **Required Adapter Seam Methods:** `AiHarnessAdapter` requires `getModelPricing(modelId: string): ModelPricingRate | undefined` and `calculateCallSpend(usage: ModelCallUsage): PricedModelCallUsage` directly on the interface, and `GenerateOptions.onUsage` emits `PricedModelCallUsage` priced via `this.calculateCallSpend(...)`. This guarantees the application tracks AI spend identically regardless of which AI backend adapter is active.
   * Maintain a deterministic, versioned `MODEL_PRICING_CATALOG` derived from the AWS Price List API for `us-east-2` covering exact `inputPerMillionUsd`, `outputPerMillionUsd`, `cacheReadPerMillionUsd`, and `cacheWritePerMillionUsd` rates for every supported foundation model ID and `us.*` / `global.*` inference profile ID.
   * **Fail-Closed Pricing Invariant (Rule 12):** `AwsBedrockHarnessAdapter` model discovery (`refreshModelAvailability`) and validation (`validateModelId`) cross-check `this.getModelPricing(modelId)`. Any model lacking a verified `us-east-2` price entry (such as `zai.glm-5.3`) is excluded from `GET /api/ai/status` and rejected with `400 InvalidModelError` until its official AWS SKU price is added to `spendPricingCatalog.ts`. Silent `$0.00` or guessed fallback pricing is forbidden.
2. **Integer Nanodollar (`10^-9` USD) Arithmetic:**
   * All cost calculations and ledger aggregations use integer nanodollars (`1 USD = 1,000,000,000 nanodollars`), where `1 token at $X per 1M tokens = Math.round(X * 1000)` nanodollars. Standard IEEE-754 safe integers (`Number.MAX_SAFE_INTEGER`) represent up to `$9,007,199.25` with zero floating-point rounding drift, converting to decimal USD strings/numbers at serialization boundaries.
3. **Dual Tool Cost Accounting (List Cost vs. Free-Tier-Adjusted Billed Cost):**
   * Every HTTP 2xx call to Google Places Text Search (`resolve_and_standardize_place`, list rate `$0.035` = `35,000,000` nanos) and Brave Web Search (`search_web`, list rate `$0.005` = `5,000,000` nanos) records both:
     * `toolListCostNanos` (unadjusted list value of the API call), and
     * `toolBilledCostNanos` (net out-of-pocket cost after applying the calendar month's `YYYY-MM` cumulative free-tier quota: default `1,000` monthly calls for Google Places Text Search Enterprise and `0` for Brave Search, configurable via environment variables).
   * The ledger reports both `totalBilledCostUsd` (`bedrockCostUsd + toolBilledCostUsd`) and `totalListCostUsd` (`bedrockCostUsd + toolListCostUsd`).
4. **Per-Turn Usage Collector & Guaranteed `finally` Flush:**
   * `GenerateOptions.onUsage` and `ScoutToolExecutionContext.onToolUsage` emit each Bedrock model call (`ConverseCommand` or `ConverseStreamCommand` iteration) and each HTTP 2xx external tool call into a per-request collector immediately upon completion of that call—before output parsing, `stopReason` assertions, or subsequent loop iterations.
   * If a streaming Bedrock call has started emitting chunks and aborts or fails before the terminal `chunk.metadata.usage` frame arrives, deterministic fallback token counts (`Math.ceil(utf8Chars / 4)`) are recorded and explicitly tagged with `usageSource: 'estimated_abort'` (versus `'exact'`).
   * Every AI route/service (`scout_chat`, `copilot_alert`, `copilot_batch_alerts`, `copilot_day_title`) flushes accumulated usage to `SpendLedgerService.recordTurnSpend()` inside a `finally` block with `status: 'success' | 'error' | 'aborted'`.
5. **Bottom-Up AWS Infrastructure Attribution + Top-Down Account Bill Reconciliation (Phase 2 Pricing Readiness):**
   * **Layer A — Per-Turn & Per-Storage-Op AWS Resource Attribution in `spend.json` (List-Rate Unmasked Cost):**
     * Even though AWS bills Lambda, S3, and CloudFront at the account level, variable consumption is driven by individual authenticated user requests. Every turn and storage operation records its allocated AWS infrastructure usage priced at full `us-east-2` list rates (unmasked by AWS Free Tier so Phase 2 unit economics never underprice marginal cost once free tiers expire):
       * **Lambda Compute (`512 MB` x86_64 in `us-east-2`):** `$0.0000166667 / GB-second` = `$0.0000083333 / second` (`8,333` nanodollars per ms of measured request `durationMs`) + `$0.20 / 1M requests` (`200` nanodollars per invocation).
       * **Amazon S3 Standard (`us-east-2`):** `PUT / COPY / POST / LIST` = `$0.005 / 1,000 requests` (`5,000` nanodollars per call); `GET / SELECT` = `$0.0004 / 1,000 requests` (`400` nanodollars per call); Storage = `$0.023 / GB-month` (`~21.4` nanodollars per KB-month). Tracked across both `SpendLedgerService` (`1 GET + 1 PUT` per turn) and `ItineraryStorageService` (`list`, `load`, `save`, `delete` per user).
       * **CloudFront Request & Egress Overhead:** `$0.0100 / 10,000 HTTPS requests` (`1,000` nanodollars per request) + `$0.085 / GB` North America/Europe data transfer out (`~0.08` nanodollars per response byte).
   * **Layer B — Top-Down AWS Cost Explorer (`--aws-bill`) & Free CloudWatch Telemetry in `./scripts/check_spend.sh`:**
     * Shared account-level costs that cannot be tied to a single API turn—such as **Amazon ECR Private image storage** (`$0.10 / GB-month`), **CloudWatch Logs ingestion/storage** (`$0.50 / GB`), **unauthenticated static SPA loads**, and **Lambda cold-start `INIT` duration**—are reconciled by `./scripts/check_spend.sh --aws-bill` via AWS Cost Explorer (`aws ce get-cost-and-usage`, opt-in via flag because AWS charges `$0.01` per Cost Explorer API call) and free CloudWatch `AWS/Lambda` & `AWS/S3` metrics (`--aws-metrics`).
   * **Layer C — Proactive Configurable Infrastructure Buffer Markup + Retroactive Empirical Calculator:**
     * Because single-user volume stays inside the AWS Free Tier and does not yet reflect realistic multi-user traffic patterns, the empirical calculator is a **retroactive corrective measure** once real usage data accumulates.
     * To guarantee the owner never loses money from day one, M4.5 also includes a **proactive, easily adjustable percentage markup factor** (`INFRA_BUFFER_MARKUP_PERCENT`, default `20%`, configurable via environment variable) on top of `fullUnitListCostNanos`. This percentage is not for profit—it builds a dedicated **Infrastructure Safety Buffer (`infraBufferReserveUsd`)** on every turn (`bufferedUserChargeUsd = fullUnitListCostUsd + infraBufferReserveUsd`) to cover shared AWS account overhead and free-tier transitions.
     * As real usage grows, `./scripts/check_spend.sh` compares `(Total Account AWS Bill + External Tool Bill)` against the accumulated `infraBufferReserveUsd` and prints the empirical break-even multiplier so the markup percentage can be tuned up or down with confidence.
6. **Atomic S3 & Local Dev Persistence + On-Demand Inspection:**
   * When `S3_STORAGE_BUCKET` is set, `SpendLedgerService` persists `s3://<bucket>/users/{email}/spend.json` using `KeyedMutex` + S3 conditional writes (`If-Match` / `If-None-Match` with retry on `HTTP 412`). When `S3_STORAGE_BUCKET` is unset (`npm run dev`), it writes `itineraries/.spend/{safeEmail}.json` locally.
   * Spend is inspectable at any time via `./scripts/check_spend.sh` (`npm run spend`), `GET /api/spend`, or direct S3 object inspection, with zero changes to the existing `infra/` AWS resources.

## 5. Implementation Notes & Code Touchpoints

* `route-builder/server/types/spend.ts`: Ledger, turn entry, model call usage, and external tool usage interfaces.
* `route-builder/server/services/spendPricingCatalog.ts`: Verified `us-east-2` Bedrock & external tool pricing table and integer nanodollar calculators.
* `route-builder/server/services/spendLedgerService.ts`: Atomic S3 (`If-Match` / `If-None-Match`) and local disk (`KeyedMutex`) spend ledger service.
* `route-builder/server/services/bedrockService.ts`, `aiService.ts`, `scoutService.ts`, `scoutTools.ts`: Immediate per-call usage emission, fail-closed pricing filter, and `finally`-block spend recording across `routes/ai.ts` and `routes/scout.ts`.
* `route-builder/server/routes/spend.ts` & `scripts/check_spend.sh`: Authenticated `GET /api/spend` endpoint and CLI spend report utility.
