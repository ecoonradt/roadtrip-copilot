## 1. Owner Outcome, Scope & Vocabulary

Through the owner's actual use, answer:
1. What usage and list-price value can be attributed to each operation/model/user?
2. How much is confirmed, unknown, or estimated, and why?
3. How does a matching period/source set compare with AWS, Google, and Brave charges?
4. What user-price scenarios follow from observed usage and explicit overhead/payment assumptions?

**Do not promise 100% capture, exact invoices from application timers, or guaranteed break-even.** A crash can prevent observation after upstream execution. Durable intent makes that uncertainty visible; provider evidence supplies the aggregate cross-check.

| Term | Meaning | Forbidden interpretation |
| --- | --- | --- |
| Confirmed usage | Provider-reported token counts, or an observed external HTTP 2xx response | Exact invoice dollars |
| Confirmed direct list value | Confirmed usage valued using its immutable rate snapshot | Net charge after credits/free usage |
| Unknown call | Intent exists without trustworthy terminal usage, including missing metadata | Zero tokens / zero dollars |
| Allocated infrastructure estimate | A documented request-time proxy priced at list rates | Billed Lambda duration or complete marginal cost |
| Provider usage charges | Provider-reported gross usage charges for a declared scope/period | Cash due after all adjustments |
| Pricing simulation | A hypothetical charge under explicit assumptions | Revenue collected, funded reserve, guaranteed recovery |

### Scope boundaries

* Instrument `/api/copilot/generate` (single/batch), `/api/copilot/day-title`, `/api/ai/scout/chat`, `/api/ai/scout/chat/stream`; record itinerary-storage request proxies separately.
* Retain immutable events; compute authenticated summaries and CLI reports. Reuse the existing S3 bucket and repository-root `itineraries/`; add no AWS resources, database, queue, paid request-metric configuration, or background billing poller.
* No Android drive-loop changes, frontend components, Stripe integration, wallet, billing enforcement, or automatic fallback to templates/CLI/local persistence on cloud failure.
* **Explicit scope correction:** M4.5 does not implement byte-time storage accounting or exact per-user infrastructure billing. It records limited request proxies and reports provider/account residuals. Snapshot sizes are diagnostics only. This replaces, rather than silently weakens, ADR-0013's unsupported full-unit-cost claim.
* Optional price simulations are CLI-only and not persisted in usage events. Default report has no markup.

5. Current invocation contract is standard on-demand text without configured prompt caching, alternate service tiers, or long-context surcharge ambiguity. Normalized catalog JSON has `{ schemaVersion: 1, catalogVersion, pricingRegion: 'us-east-2', roundingPolicy: 'per-category-half-up-nanodollar', models: ModelPricingSnapshot[], tools: ToolPricingSnapshot[], infra: InfraPricingSnapshot }`. Fixtures preserve each normalized field's source mapping. Use an explicit NodeNext JSON module import with `with { type: 'json' }` and validate it as unknown data. Existing `tsconfig.server.json` already enables `resolveJsonModule`; the imported JSON must be emitted to `dist-server/data/` by `build:server`, because the runtime Docker image copies `dist-server/`, not source `server/`. **Math:** Parse decimal rate strings into integer numerator/denominator (`bigint` intermediates). For each confirmed call, round each token category's rational nanodollar amount once, half-up; sum checked safe integers. No `number * fractionalRate` accumulation. Record the rounding policy in catalog version metadata. Validate token partitions against the documented provider usage semantics; do not double-count cache tokens. Missing required `inputTokens`/`outputTokens` is unknown; absent optional cache fields may become zero only when provider semantics establish that absence means no cache usage. Keep provider usage units in test fixtures. Quantization and provider invoice rounding mean valuations need not equal final invoice cents.

`NANOS_PER_USD = 1_000_000_000`. At the illustrative Lambda rate `$0.0000166667/GB-second`, `512 MB` yields approximately **8.33335 nanos/ms**, not 8,333. A 12-second request plus the illustrative 200-nano request fee is approximately **100,200 nanos**. Verify production infrastructure rates as source fixtures too; examples are unit tests, not certification of current rates.

### 3.3 Immutable Journal, Namespace & Idempotency

`SpendJournalService` exposes:

```typescript
ensureSource(candidate: SourceManifest): Promise<SourceManifest>;
listSources(userEmail: string): AsyncIterable<SourceManifest>;
append(source: SourceManifest, event: SpendEvent): Promise<void>;
readEvents(source: SourceManifest, window: ReportWindow): AsyncIterable<SpendEvent>;
```

* Extract the exact escaping algorithm from existing `S3ItineraryStorageService.getUserPrefix()` into `userStorageNamespace.ts`; keep its existing itinerary prefix behavior byte-for-byte. Do not replace it with `encodeURIComponent(email)`. Lowercase/trim identity once; reject empty/untrusted identities, separators, traversal and invalid source/UUID/date components. Build keys internally, never accept a caller-provided S3 prefix/path.
* Cloud source root: `users/{existingSafeEmail}/spend/v1/sources/{sourceId}/`. Manifest: `source.json`. Events: `events/{turnStartYYYY-MM-DD}/{turnId}/{eventId}.json`.
* Local root: repository-root `itineraries/.spend/users/{existingSafeEmail}/sources/{sourceId}/`, same manifest/event layout. It is **not** `route-builder/itineraries/`. Resolve from module/repository location, not process CWD. Inject a temp directory in tests. Add ignore coverage for the entire `.spend/` tree; no usage receipts committed.
* Cloud `sourceId` is stable configured `production`; account ID is injected from CDK's actual account as `SPEND_AWS_ACCOUNT_ID`. Local source identity is a persistent random UUID in `itineraries/.spend/local-source.json`, created atomically, not regenerated on restarts. Local AWS account ID may be configured or null; null requires explicit operator account attribution during reconciliation and is never assumed to match production. `test` sources cannot certify live spend.
* `ensureSource`: first conditional creation wins; on duplicate, load the existing manifest and preserve its original instrumentation start. Verify immutable identity/environment/account/scope fields against configuration. A mismatch is a configuration error requiring a new source, not an in-place rewrite. Do not infer earlier coverage from old AWS charges.
* `listSources` is read-only: discover all source directories under the validated user's namespace, follow every page of S3 common prefixes/objects or local directory entries, and GET/validate each manifest. No directories means a successfully checked uninstrumented user; permission/transport failure means 503. A directory with events but a missing/corrupt manifest is an integrity failure, not an absent source and not permission to recreate it. API/CLI use this method to include retained source IDs after rotation; they must not call `ensureSource` during reads. All-user prefix discovery is a separate operator-only paginated CLI traversal, never an arbitrary user-prefix argument.
* Allocate turn/call UUIDs and timestamps once. Event IDs are `${turnId}.started`, `${callId}.started`, `${callId}.observed`, `${turnId}.finished`. Freeze canonical JSON bytes before the first write; retries must not regenerate IDs, timestamps or money.
* Canonical encoding is recursively lexicographically sorted object keys, original array order, JSON scalar escaping, no insignificant whitespace, UTF-8 without BOM and exactly one trailing LF. Hash those exact bytes with SHA-256 lowercase hex for duplicate/import/replay checks. Reject unsupported/nonfinite JSON values before encoding; one shared encoder is used by both storage modes and CLI recovery.
* S3 writes use `IfNoneMatch: '*'`, not read-modify-write counters. On 412, GET the object: identical validated canonical bytes means idempotent success; different content means `503 SpendAccountingError`/event conflict. On 409 or ambiguous network acknowledgement, verify existing content and, only if definitely absent, retry identical bytes. Consume/cancel GET streams. Bound to three application write attempts and a 3-second total append deadline using an accounting-specific signal, independent of the client-disconnect signal. If status cannot be established, fail explicitly; never create a different ID to evade a conflict. Count this traffic as accounting overhead, not user storage proxies.
* Local writes: use the existing in-process `KeyedMutex` plus atomic create-if-absent publication (write a unique temp file, then `fs.link` to final path and unlink temp; never replacement `rename` over an existing immutable event). Duplicate comparison is identical to S3. Clean temporary files in `finally`. Atomic source-identity creation uses the same create-if-absent discipline. Do not claim multi-host filesystem durability or introduce lockfile fallbacks.
* No automatic deletion/truncation or mutable `spend.json` source of truth. A legacy `spend.json` is not silently imported or reset; report a migration-required error if encountered. It was never deployed under this plan. Retain the full source journal; only report `recentTurns` is capped at 200.
* Reads validate schemas, event/source identities and state consistency; corrupt/missing paired events produce explicit partial coverage or integrity failure, never silently ignored rows. Missing source manifest means `not_instrumented`; failed S3 reads/permission errors mean 503, not an empty ledger.

### 3.4 Paid-Call State Machine & Error Fidelity

`SpendRecorder.startTurn(userEmail, operation, requestId): Promise<SpendTurn>` binds an immutable source and durable `turn_started`. `begin()` awaits `call_started` before dispatch and snapshots its verified descriptor. `observe()` writes exactly one immutable observation using the original handle. `track()` registers the promise synchronously and returns it unchanged; `drain()` waits for registered tasks/writes to settle without unhandled rejections. After `finish`, a new call is forbidden.

The recorder selects/fixes an observation once, including timestamp and serialized bytes. An accounting-write failure must not enter a catch block that manufactures a second conflicting observation. Retry/replay only that original object. Transport code distinguishes provider failure from accounting failure and never downgrades already-confirmed usage to unknown. For a truly late transport completion after a cleanup deadline, do not create a conflicting replacement observation: unresolved durable intent remains unknown and any original replayable evidence is logged; the report must not declare complete coverage.

| Situation | Required evidence / response |
| --- | --- |
| Invalid auth/body/model before any paid dispatch | Existing 401/403/400; no paid-call intent required |
| Intent persistence fails | 503 `SpendAccountingError`; do not invoke provider |
| Abort after intent but before dispatch | Persist `not_dispatched`; confirmed cost zero for this attempt |
| Non-stream response with valid usage | Observe confirmed tokens immediately, before `stopReason`, sanitization or schema parsing |
| `max_tokens`, content filter, invalid JSON after valid usage | Preserve confirmed usage; original unusable-output response remains 502 |
| Missing usage, lost non-stream response, error before first stream frame, interrupted stream without metadata | Persist unknown reason, or leave intent unresolved if process/write fails; never emit exact zero or character/4 guesses |
| Valid stream metadata then later failure | Preserve confirmed usage, error/aborted operation status |
| External HTTP 2xx with malformed body, empty results or no match | Persist confirmed request evidence before reading/parsing body; tool domain result may still fail |
| External non-2xx or network failure after dispatch | Preserve HTTP status/request ID if available; unknown potential billing unless a verified provider rule establishes otherwise; no inferred success from tool-result shape |
| Observation write fails after paid work | Stop new paid dispatch; typed error, visible incomplete accounting and replayable structured log; do not retry paid work |
| Lambda timeout/process kill | Durable intent remains unknown; unfinished turn visible; no promise that `finally` runs |

* Bedrock runtime client uses `maxAttempts: 1` (including injected-client contract tests); leave control-plane discovery retries unchanged. No automatic application retry of paid calls in M4.5. New intentional HTTP retries create new turn/call IDs because they can incur new cost; journal retry/replay reuses IDs because it does not execute providers. This is deliberate, not a blanket reliability recommendation for all AWS APIs.
* **Bind region before dispatch:** resolve the runtime region from the existing explicit option/environment/ambient AWS region-provider chain, validate it equals `us-east-2`, and construct/use the adapter-owned runtime client with that same resolved value. No silent override or `us-east-1` fallback. Mismatch/unresolvable region is a configuration error (503 before paid dispatch), not an incorrectly priced successful call. Do not read/mutate resolved `client.config`; resolve once through the same supplied region provider used to create the client. Real composition uses the owned-client factory; injected clients are test seams with an explicit region contract. Test explicit option mismatch, environment mismatch, ambient profile mismatch, missing region, and a verified us-east-2 region. Snapshot.region must agree with the resolved invocation region, even in local mode; geographic/global profile destination routing does not change this entrypoint check.
* Wrap `send()` as well as stream iteration in accounting handling. Capture `$metadata.requestId` when available, stop reason and sanitized error code. Stream unknown evidence may include raw observed UTF-8 byte count, including reasoning/tool payload bytes, but never translates it into token counts or stores raw content.

### 3.8 Provider Reconciliation, Telemetry & Simulation

**Provider imports:** `--provider-charges` accepts schema version 1 JSON with `{ provider: 'aws'|'google'|'brave', evidenceKind: 'provider_usage_report'|'provider_invoice'|'operator_entry', currency: 'USD', periodStartAt, periodEndAt, timezone, billingScopeId, sourceUrl, retrievedAt, finalized: boolean, rows }`. Period bounds are canonical ISO UTC instants of the provider's actual half-open period; timezone is its verified IANA zone (AWS UTC, Google America/Los_Angeles, Brave its verified plan). `rows` contain `{ service, skuOrUsageType, unit, quantity: string|null, usageChargeUsd: string, creditUsd: string, refundUsd: string, taxUsd: string, otherAdjustmentUsd: string }`; adjustment strings are signed provider amounts, not silently made positive. Amounts use decimal parsing, never float sums. Preserve unknown dimensions and provider source evidence. For AWS, scope ID is the 12-digit account ID; for Google/Brave, the configured opaque scope ID. Reject currency/scope mismatch or a provider period not fully enclosed by the selected CLI UTC-date window; never silently pretend a UTC month equals a Pacific month. For a Pacific month use an explicitly padded UTC range (e.g. October 1 through November 2 exclusive), then recompute comparable application calls on the **exact provider instants**, excluding UTC padding. Display `providerPeriod` next to the outer application `window`; never compare against the padded report's full aggregate. Quota scenarios with only partial provider-period evidence remain partial. Imports are not proof of user-level attribution. Operator entries cannot masquerade as independently verified provider reports. Same scope/period/view evidence is deduplicated if identical and rejected if conflicting; CE usage and final invoice cash views remain separate, never added together.

**AWS Cost Explorer:**
* Before a query determine actual current time with an injected/verified clock. Use `get-cost-and-usage`, `--metrics UnblendedCost NetUnblendedCost`, `DAILY` granularity, and groups `SERVICE` plus `RECORD_TYPE`; aggregate to the chosen period using decimal scripts/code. GetCostAndUsage does **not** accept `UNBLENDED_COST`/`NET_UNBLENDED_COST`. Net metric absence is "not supplied", not zero or a silent alternate metric.
* Use the matching account and requested `[from,to)` period. No hardcoded service filter: preserve new/unknown services, including model charges with differing billing service labels. Keep gross usage, credit/refund/tax/other adjustments separate. `Tax` is not assumed to be a service. A dedicated optional diagnostic query by `SERVICE`+`USAGE_TYPE` is permitted only under `--aws-bill` with its extra fee disclosed; do not sum unlike token/byte/request quantities.
* Handle `NextPageToken` explicitly and persist fetched responses to `--aws-evidence-file` with scope/time/query/as-of metadata. Evidence JSON is `{ schemaVersion: 1, provider: 'aws-ce', accountId, window, retrievedAt, query, rawPages, requestsAttempted, complete, errorCode }`; preserve the raw page structures rather than inventing normalized invoice rows. Cache/evidence input is accepted only through an explicit `--include-aws-evidence FILE` read-only flag (mutually exclusive with `--aws-bill`, same schema/scope/window checks); show its original timestamp, never silently substitute it for a failed live query.
* CE is an estimated operational comparison, not an exact invoice. Report each `Estimated` flag, retrieved time and current-month status; compare completed periods when available. Provider-report ingestion may lag at least a day and later adjustments can change values. Final invoice imports are a distinct cash view with rounding tolerance.
* Build a **scope bridge**: selected sources/account, source instrumentation dates, excluded fixtures, explicit local imports, pre-instrumentation coverage gaps, known manual/deployment/other activity and documented unmatched amounts. A whole-account residual is not automatically an application bug or shared infrastructure overhead. Do not silently subtract estimated allocations from net credit-adjusted bills.
* Report AWS confirmed model list value versus AWS provider gross model usage charges separately from infrastructure. Google/Brave list values and their provider charges belong in separate sections; never compare AWS total directly to AWS+Google+Brave application totals. Credits masking cash charges do not validate rates. Do not call aggregate provider data an exact per-call reconciliation or allocate account residuals to a user as measured cost.

**`--aws-metrics` is diagnostic only:**
* Function-scoped `AWS/Lambda` `Invocations`, `Duration`, `Errors`: use correct statistics/pagination/time periods; `Duration` excludes cold start/init and is not total billed duration. Existing REPORT logs/explicitly imported evidence can supply billed duration; do not enable paid instrumentation automatically.

S3 daily `BucketSizeBytes`/`NumberOfObjects` samples and current recursive LIST are not complete storage byte-time. LIST itself costs money; disclose it and avoid it when daily metrics suffice.

CloudFront request/byte telemetry must identify distribution/geography and use its global metric endpoint as documented, not assume `us-east-2` is viewer geography. Missing metrics are unavailable, not zero.

Do not label the whole mode "free"; disclose possible API/storage LIST fees, even if normally small. No custom metric/log subscriptions or background loops.

**Google/Brave free-tier scenario:**
* Direct list values never subtract free usage. Optional estimated provider-charge scenarios require explicit per-SKU quota configuration, billing scope, and baseline consumption from other sources/projects before instrumentation. No default per-user quota or claim that the billing account is dedicated.
* Google month key is computed from **each call's timestamp in `America/Los_Angeles`**, including DST, not `timestamp.slice(0,7)`. Retain UTC day rollups for app usage separately. Read enough adjacent UTC partitions/imported source events to cover the full requested Pacific month; if a UTC selection lacks part of that month, show partial quota coverage. Brave follows its independently verified plan period/allowance; do not assume it shares Google's clock or credit model.
* `--quota-config` is the only quota/baseline input. Validate exact matching provider/scope/SKU, actual IANA timezone, provider-local period boundaries, nonnegative integer request counts, and evidence references. Reject duplicate/conflicting scope+SKU+period entries. `baselineOtherRequestCount` covers all provider-period calls outside the selected journal evidence (other projects, pre-instrumentation and missing-source usage); it is not added again per user. File inputs are explicit; no env/default precedence to invent.
* Scope/env settings are metadata, not secrets: `SPEND_GOOGLE_BILLING_SCOPE_ID` / `SPEND_BRAVE_BILLING_SCOPE_ID`; null means unknown. Changing a scope requires a new source manifest. SKU/field-mask/product changes require new rate snapshots.

**Simulation math (pure, opt-in, clearly labeled):**
* Scenario cost `C` is either (a) selected matching-period gross AWS usage + external provider charges, with adjustment policy declared, or (b) confirmed direct list value + allocated infrastructure estimate + explicitly supplied overhead estimate. Choose one basis in output; never add Bedrock again to an AWS total already containing it. Unknown consumption makes results partial.
* Parser precedence is fixed: explicit mode/window/email flags override only their documented defaults; conflicting flags/files are errors, not last-one-wins. `--cost-basis provider-gross` requires matching provider evidence (`--aws-bill` plus evidence output, explicit CE evidence import, or provider-charge imports); missing external charges are partial, not zero. `--cost-basis list-proxy` requires applicable pinned list/proxy evidence; null infra makes the scenario partial/unavailable, never zero. `--overhead-usd` with provider-gross is rejected to prevent adding overhead already in the account total. Reject simulation-only flags without `--simulate`, incomplete payment flag sets, and evidence/quota inputs with mismatched currency/period/scope. Document the exact validated inputs in `simulation.assumptions`.
* `--markup-bps N` applies a nonnegative integer basis-point assumption to scenario cost; it creates no balance/reserve. `--overhead-usd DECIMAL` is an explicit estimate, never invented automatically from residuals.
* Payment scenario requires all of `--topup-count N`, `--stripe-fee-bps P`, `--stripe-fixed-usd F`; no claim that example rates apply to every transaction. Required gross receipts: `(C + N*F)/(1 - P/10000)`, rounded up to cents. Specify net-cash/gross-usage basis and tax policy. No top-up-count assumption means no fixed-fee break-even result. `P >= 10000` is invalid. Ratios with zero denominators are null/"not applicable", never infinity or guaranteed recovery.
