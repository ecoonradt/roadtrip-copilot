## 1. Objective & Explicit Non-Goals

### Objective
Instrument the application to track per-user spend across:
1. **AI model invocations** exposed through a provider-neutral `AiHarnessAdapter` seam (`GenerateOptions.onUsage`), with `AwsBedrockHarnessAdapter` encapsulating its own Bedrock token pricing via a weekly scheduled Lambda and S3/local pricing cache (`pricing/bedrock-us-east-2.json`).
2. **Paid external grounding tool requests** (`resolve_and_standardize_place` via Google Places Text Search and `search_web` via Brave Search).
3. **Per-request AWS infrastructure usage** (Lambda compute duration and request count, S3 `GET`/`PUT`/`LIST`/`DELETE` operations, and CloudFront HTTPS request count and egress bytes).

All usage is valued at standard list rates (using exact integer nanodollars, $1\text{ USD} = 10^9\text{ nanos}$) and persisted atomically at the end of each tracked operation (`finally`) to a single human-readable per-user JSON ledger (`s3://<AppDataBucket>/users/{email}/spend.json` in cloud mode; `itineraries/.spend/{safeEmail}.json` in local dev), inspectable via `GET /api/spend` and `scripts/check_spend.sh` (`npm run spend`).

### Explicit Non-Goals
* **No Bedrock Leakage Into `AiHarnessAdapter`:** The `AiHarnessAdapter` interface must remain strictly provider-neutral. How a given adapter determines model costs (e.g., AWS Bedrock price-list caching vs. another provider returning cost directly in API response headers) is an internal implementation detail of that adapter.
* **No Web Studio UI Changes:** M4.5 introduces zero frontend components, banners, or custom UI polling. Spend inspection is served via `GET /api/spend` and `scripts/check_spend.sh`.
* **No Free-Tier or Promotional-Credit Subtraction in `spend.json`:** Ledger entries always record full standard list rates so free-tier allowances and promotional credits do not mask true marginal unit costs.
* **No Multi-User Stripe Billing or Wallet Gating:** Stripe Checkout, prepaid wallets (`wallet.json`), `HTTP 402` enforcement, and the user-facing minimum model-rate charge floor for unmetered/aborted streaming AI calls (`unmeteredAiCalls > 0` / `usageComplete: false`) remain deferred to Phase 2 (Milestone 5) so M4.5's `spend.json` ledger stays strictly faithful to AWS-metered token counts.

### B. Integer Nanodollar Math & Configurable Global Service Constants (`route-builder/server/services/spendMath.ts`)

1. **Exact Integer Nanodollar Arithmetic:**
   * All monetary values are stored and summed as safe non-negative integers in nanodollars (`NANOS_PER_USD = 1_000_000_000`), using `BigInt` intermediates with half-up rounding when converting decimal USD rates (`perMillionTokensUsd`, `perRequestUsd`, `perGbSecondUsd`, `perGiBUsd`) to nanodollars.
   * `formatUsd(nanos: number): string` renders integer nanodollars as **exactly 9 decimal places**, always: `formatUsd(125_000)` → `"0.000125000"`, `formatUsd(0)` → `"0.000000000"`, `formatUsd(1_000_000_000)` → `"1.000000000"`. Derived by pure string splitting of the integer (`whole = nanos / NANOS_PER_USD`, `frac = nanos % NANOS_PER_USD` zero-padded to 9) — **never** via floating-point division, so tests assert byte-exact strings. Negative input is a programming error and throws.

2. **Configurable Global Service List Rates (`GlobalServicePricingConfig`):**
   * Default standard list rates (overridable via environment variables):
     * `GOOGLE_PLACES_COST_USD` (default `"0.035"` per `resolve_and_standardize_place` request — Google Places Text Search Enterprise SKU).
     * `BRAVE_SEARCH_COST_USD` (default `"0.005"` per `search_web` request — Brave Search Base plan).
     * `LAMBDA_GB_SECOND_USD` (default `"0.0000166667"` at `LAMBDA_MEMORY_MB = 512` MB, i.e., `0.5 GB`).
     * `LAMBDA_REQUEST_USD` (default `"0.0000002"` — `$0.20` per 1M requests).
     * `S3_GET_OR_HEAD_USD` (default `"0.0000004"` — `$0.0004` per 1,000 `GET`/`HEAD` requests).
     * `S3_PUT_OR_LIST_USD` (default `"0.000005"` — `$0.005` per 1,000 `PUT`/`LIST` requests; `DELETE` requests are free on S3 and counted for diagnostics at `$0`).
     * `CLOUDFRONT_REQUEST_USD` (default `"0.000001"` — `$0.0100` per 10,000 HTTPS requests).
     * `CLOUDFRONT_EGRESS_GIB_USD` (default `"0.085"` per GiB egress).
   * **Startup validation (no silent bad rates):** `loadGlobalServicePricingConfig()` parses every override once at module load and throws a descriptive `SpendConfigError` for empty, non-finite, or negative values (e.g. `LAMBDA_GB_SECOND_USD=abc` fails fast instead of propagating `NaN` nanodollars into every ledger line). All BigInt→`number` conversions must assert `Number.isSafeInteger(...)` and throw on overflow rather than truncating. Tests cover each invalid-override failure path.
   * **Runtime value errors are distinct from configuration errors:** a malformed rate or environment override raises `SpendConfigError`, while an invalid runtime usage count (negative, fractional, or non-numeric) raises `SpendValueError`. Step 3 and Step 4 log lines therefore distinguish a bad rate from a bad measurement.

### C. Bedrock-Specific Pricing Normalization, S3/Local Cache & Weekly Refresh Lambda (`route-builder/server/services/bedrockPricing.ts`, `route-builder/server/services/bedrockPricingCache.ts`, `route-builder/server/handlers/refreshBedrockPricing.ts`, `infra/`)

> **Architectural Boundary:** Everything in this section is strictly an internal implementation detail of `AwsBedrockHarnessAdapter`. No other AI provider adapter or route depends on these modules.

1. **Bedrock Pricing Catalog Schema (`BedrockPricingCatalog` in `bedrockPricing.ts`):**
   ```ts
   export interface BedrockModelTokenRate {
     modelId: string; // canonical model ID (e.g. 'us.moonshotai.kimi-k3', 'us.amazon.nova-2-lite-v1:0')
     foundationModelId: string;
     providerName: string;
     inputPerMillionUsd: string;
     outputPerMillionUsd: string;
     cacheReadPerMillionUsd: string | null;
     cacheWritePerMillionUsd: string | null;
   }

   export interface BedrockPricingCatalog {
     schemaVersion: 1;
     region: 'us-east-2';
     refreshedAt: string; // ISO-8601 UTC timestamp
     models: Record<string, BedrockModelTokenRate>;
     unpricedModelIds: string[];
   }
   ```
   * `calculateBedrockCallCostNanos(usage, rate: BedrockModelTokenRate): number` computes exact integer nanodollars across `inputTokens`, `outputTokens`, `cacheReadInputTokens`, and `cacheWriteInputTokens` using `spendMath.ts`.

2. **Bedrock Price List Normalization (`bedrockPricing.ts`):**
   * **Source contract (literal):** Use `@aws-sdk/client-pricing` (`new PricingClient({ region: PRICING_API_REGION })`) and call `GetProductsCommand` **once per service code for all three Bedrock service codes** — `AmazonBedrock`, `AmazonBedrockFoundationModels`, and `AmazonBedrockService` — passing `{ ServiceCode, Filters: [...], MaxResults: 100, NextToken }`, with `MAX_PRICING_PAGES` applied **per service code**. Partner/marketplace models (including the `us.moonshotai.kimi-k3` Scout default and Anthropic models) are published under the latter two service codes, so querying `AmazonBedrock` alone would leave them unpriced. Each `PriceList` entry is a **JSON-encoded string** parsed into `{ product: { attributes: Record<string,string> }, terms: { OnDemand: Record<string, { priceDimensions: Record<string, { unit: string; pricePerUnit: { USD: string } }> }> } }`; normalization reads `terms.OnDemand[*].priceDimensions[*].pricePerUnit.USD` and converts its `unit` (`"1K tokens"` vs `"1M tokens"`) to per-1M-token rates explicitly. Use `DescribeServicesCommand` only to enumerate supported filter keys.
   * **Global-endpoint exception (explicit deviation from the "never hardcode `us-east-1`" rule):** The AWS Price List Query API is hosted **only** in `us-east-1` and `ap-south-1`. `PRICING_API_REGION` is therefore pinned to `'us-east-1'` **for the pricing client alone**, with a code comment stating this is a global service endpoint rather than a regional-resource region. Every other client (`S3Client`, `BedrockRuntimeClient`, `BedrockClient`, `SSMClient`) keeps the ambient `region ? { region } : {}` pattern. The **priced region remains `us-east-2`** (`BedrockPricingCatalog.region === 'us-east-2'`); the pricing client endpoint region and the priced region are deliberately different.
   * **Bounded fetch:** `MAX_PRICING_PAGES = 20` pages and `PRICING_FETCH_TIMEOUT_MS = 45_000`; exceeding either fails loudly (`PricingUnavailableError`) instead of returning a silently partial catalog. The total budget is a hard deadline, not only a between-page check: every page is issued under an `AbortSignal` that fires when the remaining budget is exhausted, so one stalled page can never overrun the budget by a full socket timeout.
   * **No empty catalog (fail loudly, never a zero-rate catalog):** an empty `PriceList` response from `AmazonBedrock` or `AmazonBedrockFoundationModels`, a fetch with no discovered models to price (raised before any request is issued), and a fetch that resolves zero priced models all raise `PricingUnavailableError`. A truncated, filtered-away, or silently emptied upstream response never produces a "valid" catalog whose every model is unpriced.
   * **Required IAM (provisioned in Step 2):** `pricing:GetProducts` and `pricing:DescribeServices` on `*` (these APIs do not support resource-level permissions), in addition to `bedrock:ListFoundationModels` and `bedrock:ListInferenceProfiles`.
   * **Two-path deterministic matching against `us-east-2` entries:**
     1. **Usagetype-key path (`AmazonBedrock` / `AmazonBedrockService`):** Evaluates candidate keys in strict precedence — verbatim `foundationModelId`, trailing `-vN:M`/`-N:M` version suffix stripped, trailing `-instruct` stripped, committed `BEDROCK_PRICING_KEY_ALIASES` (`amazon.nova-2-lite-v1:0` → `Nova2.0Lite`, `amazon.nova-pro-v1:0` → `NovaPro`, `amazon.nova-lite-v1:0` → `NovaLite`, `amazon.nova-micro-v1:0` → `NovaMicro`, `amazon.nova-premier-v1:0` → `NovaPremier`, `deepseek.v3-v1:0` → `deepseek.v3.1`, `deepseek.r1-v1:0` → `DeepSeek-R1`, `mistral.pixtral-large-2502-v1:0` → `PixtralLarge2502`, `moonshot.kimi-k2-thinking` → `moonshotai.kimi-k2-thinking`, `zai.glm-5` → `zai.glm5`), and vendor-prefix-stripped bare keys. Matches case-insensitively when the `USE2-`-stripped `usagetype` starts with `<key>-` followed immediately by the dimension grammar (`(?:instruct-)?(mantle|input|output|text-input|text-output|cache)(?:-|$)`). A key wins only when it yields a complete, non-conflicting input+output pair at the model's target scope (`global` for `global.*` profiles; `regional` otherwise) from a single service code. **Precedence stops at the first key that yields any candidates:** an ambiguous key (two complete service codes, or differing input/output rates within one service code) leaves the model unpriced instead of letting a lower-precedence bare key win, while a key that yields only incomplete dimensions (for example a cache dimension with no input/output pair) continues to the next key.
     2. **Marketplace display-name path (`AmazonBedrockFoundationModels`):** Matches `product.attributes.model` to the discovered model's `modelName` after stripping optional regional/profile (`US`/`Global`/`EU`/`APAC`) and provider-name prefixes on both sides, requiring exact case-insensitive equality and a single unique `foundationModelId` among discovered models sharing that normalized name.
   * **Standard on-demand text filtering & deduplication:** Excludes audio/image/video, provisioned throughput, reserved, custom/fine-tuned, `priority`, `flex`, `batch`, `latency-optimized`, `long_ctx`/`long-context`, and 1-hour cache-write SKUs (an alphanumeric-bounded `1h`/`1hr`/`1hour` marker in dashed, underscore-joined, and concatenated `cachewrite1h` forms). Dimension and variant detection read **SKU identity only** (usage type, inference type, feature); the model display name is never matched against dimension, cache, or `1h` keywords, so a model whose name happens to contain those words is neither dropped nor misclassified. Scope detection additionally reads the display name, so a SKU that names itself `Global` in `product.attributes.model` is a global rate even when its usagetype carries no scope marker. Duplicate SKUs for the same `(serviceCode, scope, dimension)` that publish the **exact same per-1M USD rate** (such as `-mantle-*-standard` and non-mantle `*-input-tokens` entries in `AmazonBedrock`) collapse to that single rate; distinct conflicting rates for a dimension resolve to `null` (leaving the model in `unpricedModelIds` if input or output conflicts). A single SKU that publishes **more than one distinct per-1M rate** (tiered or multi-dimension terms) is ambiguous and is never priced at one of its rates. All dimensions for a priced model must originate from a single service code.
   * **Zero rates are never a list price:** a `$0` input or output rate leaves the model unpriced, and `validateBedrockPricingCatalog` rejects such a catalog. A `$0` cache rate is legitimate (Amazon Nova 2 Lite publishes free cache writes) and is preserved as `0.000000000`.
   * Never invents or guesses a rate: any discovered model whose input/output token rates cannot be deterministically matched is recorded in `unpricedModelIds` and omitted from `models`.
   * **Tests use committed JSON fixtures** of the `GetProducts` response shape (compact, multi-vendor) — no live network in tests.

3. **S3 & Local Pricing Cache (`bedrockPricingCache.ts`):**
   * **Cloud storage path (when `S3_STORAGE_BUCKET` is set):** `s3://<S3_STORAGE_BUCKET>/pricing/bedrock-us-east-2.json`.
   * **Local dev path (when `S3_STORAGE_BUCKET` is unset):** `<repo-root>/itineraries/.spend/pricing/bedrock-us-east-2.json` (isolated from production S3 per ADR-0004).
   * In-memory cache TTL of 5 minutes for reading the catalog; catalog is considered **stale** when `Date.now() - Date.parse(catalog.refreshedAt) > 7 * 24 * 60 * 60 * 1000` (7 days).
   * The web application never calls the AWS Price List API on demand during user requests: if the catalog is older than 7 days, it continues using the cached rates, logs a warning, and marks `isStale = true`.
   * If a catalog reload from S3/disk fails when a previous valid catalog already exists in memory, retains the last valid catalog and marks `isStale = true` (logging a warning); if no valid catalog exists on S3/disk or in memory, fails loudly with `PricingUnavailableError` (`HTTP 503`).

4. **Integration Inside `AwsBedrockHarnessAdapter` (`bedrockService.ts`):**
   * `getAvailableModels()` and `validateModelId()` intersect discovered account-eligible models with `catalog.models` so models lacking a resolved price in the catalog are excluded from `getAvailableModels()` and rejected on direct `validateModelId()` calls (`InvalidModelError` / `503` if pricing cache itself is unavailable). **Literal status mapping:** an unknown or account-ineligible `modelId` → `InvalidModelError` surfaced as `HTTP 400`; a valid-but-unpriced `modelId`, or a pricing cache that is unavailable, → `HTTP 503` with a message naming the model and the pricing state. The configured defaults (`us.moonshotai.kimi-k3`, `us.amazon.nova-2-lite-v1:0`) **must resolve a price**, so Step 2 verification adds a fixture-backed check that both defaults remain selectable and that `GET /api/ai/status` reports either `available: true` or an explicit `503` — never a silently empty model list.
   * In both `generate()` (`ConverseCommand`) and `generateStreamWithTools()` (`ConverseStreamCommand`), immediately upon receiving response usage metadata (before `stopReason` checks or output schema validation), `AwsBedrockHarnessAdapter` computes `costNanos` from the model's `BedrockModelTokenRate` and invokes `options?.onUsage?.({ providerId: this.id, modelId, inputTokens, outputTokens, cacheReadInputTokens, cacheWriteInputTokens, costNanos, pricingStale, usageComplete: true })`.
   * If a call in `generateStreamWithTools()` or `generate()` aborts or errors after dispatch before usage metadata arrives (or returns without usage metadata), `AwsBedrockHarnessAdapter` invokes `options?.onUsage?.({ providerId: this.id, modelId, inputTokens: 0, outputTokens: 0, cacheReadInputTokens: 0, cacheWriteInputTokens: 0, costNanos: 0, pricingStale, usageComplete: false })`.

5. **Weekly Scheduled Refresh Lambda, Failure Alerting & CDK (`route-builder/server/handlers/refreshBedrockPricing.ts` & `infra/`):**
   * Lightweight handler (`refreshBedrockPricing.handler`) that discovers compatible Bedrock models in `us-east-2`, fetches and normalizes current AWS Bedrock pricing, and writes `pricing/bedrock-us-east-2.json` to `S3_STORAGE_BUCKET` (in cloud) or `itineraries/.spend/pricing/bedrock-us-east-2.json` (when invoked locally via `npm run refresh:pricing`).
   * **Packaging decision (CDK, Step 2): provision a separate standard Node.js Lambda — do *not* reuse the web image.** `route-builder/Dockerfile` bakes in **AWS Lambda Web Adapter** (`/opt/extensions/lambda-adapter`, `AWS_LWA_INVOKE_MODE=response_stream`, `AWS_LWA_READINESS_CHECK_PATH=/api/health`, `PORT=3001`); any binary in `/opt/extensions/` runs on every cold start and the adapter requires the container `cmd` to be a process serving HTTP on `:3001`. Overriding `cmd` to run a plain `export async function handler(event)` module would therefore crash with `Runtime.ExitError` during init.
     Use `lambda.NodejsFunction({ entry: path.resolve(__dirname, '../../route-builder/server/handlers/refreshBedrockPricing.ts'), runtime: lambda.Runtime.NODEJS_24_X, memorySize: 512, timeout: cdk.Duration.seconds(60), bundling: { minify: true, externalModules: [] } })` and add `esbuild` to `infra/package.json` devDependencies (CDK bundling requires a resolvable esbuild). The handler module must stay lightweight — it may import only `bedrockPricing.ts` + `bedrockPricingCache.ts` and AWS SDK clients, never the Fastify app or `dist-server/index.js`.
   * Provisioned in `infra/lib/roadtrip-cloud-stack.ts` as an on-demand Lambda (`512 MB`, `60s` timeout, zero provisioned concurrency) triggered weekly by an EventBridge Scheduler `Schedule` (`cron(0 6 ? * MON *)` UTC) using `aws-scheduler-targets.LambdaInvoke` so the scheduler role receives the required `lambda:InvokeFunction` grant automatically, plus a CloudWatch Alarm on function errors wired to an SNS Alert Topic (`PricingRefreshAlertTopic`) for failure notifications.
   * Least-privilege IAM on `RefreshBedrockPricingFunction` only: `s3:GetObject` / `s3:PutObject` on `<AppDataBucket>/pricing/*`, `bedrock:ListFoundationModels`, `bedrock:ListInferenceProfiles`, `pricing:GetProducts`, `pricing:DescribeServices`. (`FastifyApiFunction` does not receive `pricing:*` permissions).
   * **`infra/test/roadtrip-cloud-stack.test.ts` must assert** the new function's existence, the 512 MB / 60s configuration, the weekly schedule expression, the CloudWatch error alarm + SNS topic, and that both the Lambda role policy statements and the scheduler invoke grant are present.
   * **Local bootstrap / first cloud seed:** in local dev, running `npm run refresh:pricing` writes `itineraries/.spend/pricing/bedrock-us-east-2.json`; if absent when AI endpoints are called, that surfaces as an explicit `503` error — never a zero-rate catalog. For cloud, the first catalog is created by a one-time manual operator invoke of `RefreshBedrockPricingFunction` after deploy; this is deliberately **not** scripted into `deploy_cloud.sh` or CI/CD.

### D. Atomic Per-User Spend Ledger Service (`route-builder/server/services/spendLedgerService.ts`)

1. **Storage Locations & Concurrency Safety:**
   * **Cloud (`S3_STORAGE_BUCKET` set):** `s3://<S3_STORAGE_BUCKET>/users/{safeEmail}/spend.json`. `{safeEmail}` comes from a new **exported** `sanitizeEmailForObjectKey(email: string): string` in `route-builder/server/services/spendLedgerService.ts`, refactored out of the existing inline sanitizer in `S3ItineraryStorageService.getUserPrefix()` (percent-encode every character outside `[a-z0-9.@+_-]` as uppercase `%XX`) and reused by both call sites so cloud and local keys can never drift. `scripts/check_spend.sh` resolves the object key through the same function via a small `node -e` helper rather than re-implementing percent-encoding in bash; a regression test asserts itinerary prefixes and spend keys agree for mixed-case, `+`, and non-ASCII addresses. Uses `KeyedMutex` + S3 `ETag` conditional writes (`If-None-Match: "*"` on initial creation, `If-Match: <etag>` on updates, with bounded retry on `HTTP 412 Precondition Failed`).
   * **Local Dev (`S3_STORAGE_BUCKET` unset):** `<repo-root>/itineraries/.spend/{safeEmail}.json`, guarded by `KeyedMutex` and atomic temp-file write + rename.
   * Ensure `.spend/` under `itineraries/` is gitignored so local spend ledgers and local pricing caches are never committed.

2. **Ledger Aggregation (`recordTurn(userEmail: string, turn: SpendTurnRecord): Promise<UserSpendLedger>`):**
   * Reads existing `UserSpendLedger` (or initializes an empty schema v1 ledger for `userEmail`), adds `turn` metrics into:
     * `totals`
     * `byMonth[turn.timestamp.slice(0, 7)]`
     * `byDay[turn.timestamp.slice(0, 10)]`
     * `byModel["${turn.providerId}:${turn.modelId}"]` (for turns with AI calls)

Response payload bytes are still recorded in local mode for diagnostics but valued at `$0`.

3. **Turn Accumulator Contract (`route-builder/server/services/spendInfraMeter.ts`, types in `route-builder/server/types/spend.ts`):**
   ```ts
   export type SpendEnvironment = 'cloud' | 'local';

   export interface SpendTurnContext {
     turnId: string;                 // crypto.randomUUID()
     startedAt: number;              // Date.now() at request entry
     environment: SpendEnvironment;  // 'cloud' when S3_STORAGE_BUCKET is set, else 'local'
     operation: SpendOperation;
     email: string;
     addAiUsage(event: AiUsageEvent): void;
     addToolUsage(event: ToolUsageEvent): void;
     snapshotInfra(): InfraUsageMetrics;
   }
   ```
   * Routes obtain the context through a single Fastify `onRequest` hook registered in `route-builder/server/app.ts` that runs the remainder of the request inside one `AsyncLocalStorage` store (`runInSpendTurnContext(operation, fn)`), so all five instrumented route files share identical semantics and abort paths still resolve a context.
   * `addAiUsage` / `addToolUsage` are **synchronous, mutation-only** increments (no awaits inside), making them safe for parallel `Promise.all` tool-loop execution; `onUsage` / `onToolUsage` callbacks may return promises, and the caller must collect them with `Promise.all` before the flush rather than relying on emission order.
   * Tool loops bounded by `MAX_TOOL_ITERATIONS` emit exactly one `AiUsageEvent` per model call — an N-iteration loop yields N events plus any paid tool events; integration tests assert these counts.

4. **End-of-Turn Flush Semantics (applies to every instrumented route):**
   * The accumulated turn is flushed **once per request**. Whether it is flushed from the route's `finally` block or from an early `reply.raw.on('close')` handler (already present in `server/routes/scout.ts`), the first flush marks the context `flushed = true` and later paths become no-ops — **double-counting an aborted turn is the single highest-impact correctness risk in this milestone** and must be covered by a test.
   * Every SSE keep-alive `setInterval` (e.g. `server/routes/scout.ts:233`) is cleared in the route's `finally` block **and** in the corresponding `close` handler; no timer may outlive the request.
   * `TurnStatus` derivation (literal): `'success'` when the turn completed without a thrown error; `'error'` when the handler threw or returned 5xx; `'aborted'` when the client disconnected (`reply.raw.aborted` / socket `close`) before the turn completed.
   * In cloud mode (Lambda Web Adapter) the ledger write is **awaited before the reply ends** — never backgrounded, since execution freeze risks dropping the write. Use `KeyedMutex.runExclusive(key, fn, { timeoutMs: 2000 })`; a `LockTimeoutError` is logged and swallowed for the spend path only.
   * If a ledger write fails for any other reason, log a structured error without crashing an already-streaming SSE response or masking an upstream provider error.

### Live AWS Price List API payload structure in `us-east-2` (`bedrockPricing.ts`)

Read-only verification against the live AWS Price List Query API (`us-east-1` endpoint, `regionCode = us-east-2`) across `AmazonBedrock` (921 entries, 10 pages), `AmazonBedrockFoundationModels` (314 entries, 4 pages), and `AmazonBedrockService` (18 entries, 1 page) established the exact payload rules reflected in §2.C.2:

* **Service code & unit split:** `AmazonBedrock` publishes token rates with `unit: "1K tokens"` (except `xai.grok-4.3` at `1M tokens`) and encodes model identity in `usagetype` (`USE2-<key>-...`); `AmazonBedrockFoundationModels` publishes marketplace models (including all Anthropic models and `OpenAI GPT-6 Astra`) with `unit: "1M tokens"` and generic `USE2-MP:USE2_*` `usagetype` strings where model identity appears only in `product.attributes.model`. `AmazonBedrockService` in `us-east-2` currently contains only reserved/long-context SKUs.
* **Duplicate mantle & non-mantle SKUs at identical rates:** For several partner models in `AmazonBedrock` (e.g. `deepseek.v3.2`, `moonshotai.kimi-k2.5`, `minimax.minimax-m2.1`, `minimax.minimax-m2.5`, `mistral.devstral-2-123b`, `nvidia.nemotron-super-3-120b`, `writer.palmyra-vision-7b`, `zai.glm-4.7`, `zai.glm-4.7-flash`), AWS publishes both a `-mantle-*-standard` SKU and a non-mantle `*-input-tokens`/`*-output-tokens` SKU with the exact same USD price. `singleDimension` therefore deduplicates by normalized per-1M USD rate and only rejects a dimension when multiple matched SKUs publish different rates.
* **Tier & variant exclusions:** In addition to `priority`, `flex`, `batch`, and `1h` cache-write SKUs, the `us-east-2` catalog includes `-latency-optimized` SKUs (e.g. `USE2-NovaPro-input-tokens-latency-optimized` on `Nova Pro Latency Optimized`) and `_long_ctx_` / `-long-context-` SKUs (e.g. `USE2-MP:USE2_input_tokens_long_ctx_standard-Units` on `OpenAI GPT-6 Astra` and `Claude Haiku 5.5`), which `classify()` excludes so standard on-demand rates resolve unambiguously.
* **Deterministic key normalization & alias bridge:** Case-insensitive key prefix matching with version-suffix (`-vN:M`/`-N:M`), `-instruct`, and vendor-prefix stripping plus optional `instruct-` dimension prefixing resolves standard partner, Meta Llama (`USE2-Llama3-1-8B-*`), and Qwen (`USE2-qwen.qwen3-coder-30b-a3b-instruct-mantle-*`) models directly, while `BEDROCK_PRICING_KEY_ALIASES` bridges the 10 foundation model IDs whose `AmazonBedrock` `usagetype` stem differs from `foundationModelId` (`amazon.nova-*`, `deepseek.v3-v1:0`, `deepseek.r1-v1:0`, `mistral.pixtral-large-2502-v1:0`, `moonshot.kimi-k2-thinking`, `zai.glm-5`).

### Pricing catalog guardrails and import-time coupling (`bedrockPricing.ts` & `spendMath.ts`)

* **Guardrails against a silently wrong catalog.** The normalizer and the fetcher fail loudly on every path that could otherwise yield a plausible-but-wrong catalog: an empty `PriceList` response from `AmazonBedrock`/`AmazonBedrockFoundationModels`, a fetch with no discovered models to price, a fetch that resolves zero priced models, a `$0` input or output rate, a SKU that publishes more than one distinct per-1M rate, and a key whose result is ambiguous. Each of these ends as `unpricedModelIds` or as a `PricingUnavailableError` — never as a rate that bills the user `$0` or the wrong amount. A `$0` cache-write rate stays legitimate (`Amazon Nova 2 Lite`).
* **Dimension detection reads SKU identity only.** Usage type, inference type, and feature determine the dimension and the variant exclusions; the model display name widens the conservative product exclusions and carries the `Global` scope marker when the usagetype has none. A model name that merely contains `1h`, `cache`, `read`, or `write` never causes a false drop or misclassification.
* **Key precedence stops at the first ambiguous key.** A key that yields two complete service codes, or differing input/output rates within one service code, leaves the model unpriced rather than falling through to a lower-precedence vendor-stripped key. A key that yields only incomplete dimensions still continues to the next key.
* **Hard total deadline.** Each `GetProducts` page is issued under an `AbortSignal` bounded by the remaining fetch budget, so a stalled page cannot overrun `PRICING_FETCH_TIMEOUT_MS` by a full socket timeout.
* **Import-time coupling of the global service rates (accepted, deliberate).** `GLOBAL_SERVICE_PRICING` is resolved when `spendMath.ts` is imported, and `bedrockPricing.ts` imports `spendMath.ts` for its nanodollar helpers. A malformed `CLOUDFRONT_REQUEST_USD`/`CLOUDFRONT_EGRESS_GIB_USD` (or any other) override therefore crashes the weekly pricing-refresh Lambda even though it uses none of those rates. This is intended fail-fast behavior: a bad override is a configuration error that must surface immediately rather than value spend at a wrong rate, and every process that imports `spendMath.ts` — the web studio, the pricing-refresh Lambda, and the ledger tooling — inherits the same validation. The override set must be valid for all of them.

### Step 2 CDK `NodejsFunction` bundling and default-model catalog protection (`refreshBedrockPricing.ts`, `bedrockPricingCache.ts`, `roadtrip-cloud-stack.ts`)

* **Cross-package `NodejsFunction` root configuration:** Because `infra/` has its own `package-lock.json` while `refreshBedrockPricing.ts` lives under `route-builder/server/handlers/`, `NodejsFunction` requires explicit `projectRoot: path.resolve(__dirname, '../../route-builder')` and `depsLockFilePath: path.resolve(__dirname, '../../route-builder/package-lock.json')` so esbuild resolves `@aws-sdk/client-bedrock`, `@aws-sdk/client-pricing`, and `@aws-sdk/client-s3` from `route-builder/` without raising `PathNotUnderRoot`.
